# Тест-дизайн

## Классы эквивалентности и границы

| Поле | Допустимые классы | Недопустимые классы | Границы |
| --- | --- | --- | --- |
| Номер | 16 ASCII-цифр с Луном, с пробелами, ведущие нули | другая длина, ошибка Луна, буквы, дефисы, табуляция, Unicode-цифры | 15 / 16 / 17 символов после удаления пробелов |
| Владелец | два латинских слова, смешанный регистр, пробельные разделители | одно/три слова, короткое первое/второе слово, кириллица, диакритика, цифры, дефис, апостроф | 1 / 2 буквы в каждом слове; 1 / 2 / 3 слова |
| Дата | MM/yy, MM/yyyy, прошлый год | неправильный разделитель, ширина частей, буквы, пробелы, Unicode-цифры | месяцы 00 / 01 / 12 / 13; год длиной 1 / 2 / 3 / 4 / 5 |
| CVV | три ASCII-цифры, ведущие нули | другая длина, буквы, пробелы, Unicode-цифры | 2 / 3 / 4 символа; 000 / 999 |
| Лун | корректные контрольные суммы, произвольная длина, пробелы | неправильная сумма, недопустимые символы | удвоение с результатом до 9 и больше 9, чётные/нечётные позиции |

Для каждого поля дополнительно проверяются пустая строка, только пробелы, None, число, bool, список и объект. Ожидания записаны в JSON вручную при подготовке данных, а не вычисляются проверяемыми методами во время тестирования.

## Одна ошибка в полной карте

В PDF требуется не более одного неправильного поля в `full_card_cases.json`. Этот набор содержит корректную карту и все негативные примеры отдельных полей на фоне трёх корректных. Так проверяется, что каждое поле способно отклонить карту. Дополнительный тест контролирует число ошибочных полей.

## Попарное исследование

Одна ошибка за раз и pairwise — разные техники. Для четырёх параметров с уровнями «корректно» и «некорректно» полный перебор содержит 16 комбинаций. У каждой из шести пар параметров есть четыре сочетания уровней: всего 24 парных взаимодействия.

В `pairwise_cases.json` отдельно записан сокращённый набор, покрывающий все 24 взаимодействия. Для корректного уровня используются значения базовой карты, для некорректного — null. Набор получен последовательным выбором комбинации, закрывающей наибольшее число ещё не покрытых пар. Это исследование покрытия двух уровней, а не всех возможных значений полей. Несколько ошибок в одной строке допускаются только здесь, поэтому правило из PDF для `full_card_cases.json` соблюдено.

`test_all_pairs_covered` независимо проверяет наличие всех четырёх сочетаний для каждой пары. Детальные ошибки формата и границы остаются в отдельных наборах.

## Ограничения

100% покрытия строк и ветвей не означает проверку всех возможных входов. Не добавлены проверка банка, реального существования карты, текущей даты, максимальной длины имени или вызовы платёжных сервисов: таких требований нет. Учебный сайт по ссылке из PDF при обращении вернул HTTP 403; его поведение не использовалось как основание для изменения правил PDF.
