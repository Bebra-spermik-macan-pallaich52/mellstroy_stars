# Card Project: проверка данных банковской карты

Учебный Python-проект по заданию «Проверка карты: параметризация». Реализованы все пять методов класса Card, дополнительный алгоритм Луна, данные в JSON, фикстуры, параметризованные unit-тесты и проверка покрытия.

## Установка

Нужен Python 3.10 или новее. Откройте терминал в папке `card_project`.

```text
python -m venv venv
```

Активация в Windows CMD:

```text
venv\Scripts\activate
```

Активация в Windows PowerShell:

```text
.\venv\Scripts\Activate.ps1
```

Активация в Linux/macOS:

```sh
source venv/bin/activate
```

Установка зависимостей:

```text
python -m pip install -r requirements.txt
```

## Запуск программы

```text
python -m app.main
```

Введите четыре поля. Программа сообщает, корректны ли данные. CVV вводится скрыто. Для учебного примера используйте номер `4111111111111111`, имя `Ivan Ivanov`, дату `12/2027` и CVV `123`. Программа ничего не оплачивает и не сохраняет введённые данные.

## Правила

- Все поля должны быть строками. Числа, None, списки и другие типы возвращают False.
- Номер: удаляются обычные пробелы, затем проверяются ровно 16 цифр ASCII и алгоритм Луна. Табуляция, дефисы, переводы строки и Unicode-цифры запрещены.
- Владелец: ровно два слова из A–Z/a–z, минимум две буквы в каждом. Регистр свободный. Слова выделяются через split(): лишние пробелы и другие пробельные разделители допустимы. Имя с дефисом, апострофом, цифрами или диакритикой не проходит.
- Дата: строго MM/yy либо MM/yyyy, месяц 01–12. Пробелы по краям запрещены. Проверка срока относительно сегодняшнего дня не добавлена: её нет в условиях. Год ограничен количеством цифр; 00 и 0000 допустимы в рамках этих условий, это не преобразование в объект календарной даты.
- CVV: ровно три цифры ASCII. Ведущие нули допустимы; пробелы не удаляются.
- Общая проверка возвращает True только при корректности всех четырёх полей.

В основном тексте PDF Лун указан как дополнительное задание, а в образце README уже включён в правила номера. Здесь реализован вариант с Луном: номер `1234567890123456` отклоняется несмотря на правильную длину. Отдельный `luhn_check` работает с любой непустой последовательностью цифр и поддерживает пример `79927398713`. Проверка 16 символов находится в `is_valid_card_number`. Нулевые номера удовлетворяют формальным условиям; проверка существования карты или банка не требуется.

## Структура

```text
card_project/
  app/
    __init__.py
    main.py
    utils/
      __init__.py
      card.py
  tests/
    __init__.py
    conftest.py
    test_card.py
    test_design.py
    data/
      card_number_cases.json
      holder_name_cases.json
      expiry_date_cases.json
      cvv_cases.json
      full_card_cases.json
      luhn_cases.json
      pairwise_cases.json
  requirements.txt
  pytest.ini
  README.md
  TEST_DESIGN.md
  VALIDATION.md
  .gitignore
```

Пустые `__init__.py` обозначают пакеты Python по структуре из задания. `conftest.py` читает JSON и предоставляет фикстуры; pytest_generate_tests задаёт отдельный тест для каждой записи с понятным ID. `test_design.py` дополнительно проверяет ограничение одной ошибки и полноту попарного покрытия. Тестовые значения не дублируются в Python-тестах.

## Тестирование

Все команды выполняются внутри `card_project` после активации окружения:

```text
python -m pytest -v
python -m pytest tests/test_card.py -v
python -m pytest tests/test_card.py::TestCard -v
```

## Покрытие

Команда из задания:

```text
python -m pytest --cov=app/utils --cov-report=html:coverage_re
```

Более строгая проверка, включая ветвления:

```text
python -m pytest --cov=app/utils --cov-branch --cov-report=term-missing --cov-report=html:coverage_re --cov-fail-under=100
```

Откройте `coverage_re/index.html` в браузере. Отчёт и виртуальное окружение создаются локально и исключены из Git. Покрытие измеряется для класса Card (`app/utils`), а не для интерактивного ввода. Результаты выполненных проверок — в `VALIDATION.md`, описание тест-дизайна — в `TEST_DESIGN.md`.
